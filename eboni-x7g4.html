Ruzuku how-to

Ruzuku is built from two pieces: Modules (the containers, like chapters) and Lessons (where the actual content lives — text, video, files, quizzes, discussions). Our 13 course modules map straight onto Ruzuku modules; each module's sections become lessons.

Add a module

  1. In the course, open Manage Course → Modules & Lessons.
  2. Click Create Module at the top of the outline.
  3. Give it a clear name (e.g., "Module 1: [title from the course doc]") and click Save.

Add a lesson & paste text

  1. Inside the module, click Add Lesson. Keep each lesson to one job — one topic, one video, or one activity.
  2. Paste the learner-facing text from the course doc into the lesson editor.
  3. Paste as plain text (Ctrl+Shift+V / Cmd+Shift+V) so Word styling doesn't come along, then re-apply headings in Ruzuku. This keeps formatting consistent.
  4. Re-attach the links — in the master doc every URL sits right beside its anchor phrase; highlight the phrase in Ruzuku and apply the URL.
  5. End most lessons with something to do — a reflection prompt, a quick check, or a discussion post.

Build the quizzes

  1. Each knowledge check in the master doc is a numbered, ready-to-build quiz: Q1–Q5 with options A–D and a ✓ on the correct answer.
  2. Create a quiz (or self-check) in Ruzuku, copy each question and its four options, and mark the ✓ option correct in the settings.
  3. Never paste the ✓ key into anything learner-facing.

Embed a YouTube / W3C video

  1. On YouTube, click Share → Embed and copy the embed code.
  2. In the lesson, open the Add media dropdown and choose HTML or embed code.
  3. Paste the embed code and click Insert HTML.

Upload a video file directly

  1. Manage Course → Modules & Lessons → select the lesson.
  2. Click Add media → Video or audio file.
  3. Drag-and-drop the file (or record in-browser). On the Pro plan, Ruzuku auto-generates captions & a searchable transcript — turn these on for every video (this is an accessibility course; we practice what we teach).

Gates & drip (the checkpoint + certificate steps)

  • Use completion requirements so learners must finish a module before the next unlocks — that's how the mid-course Checkpoint gate works (Modules 8–11 stay locked until the checkpoint is passed).
  • For the certificate step, use an assignment/upload lesson so learners submit their DHS Trusted Tester or W3C certificate to advance.
  • Set drip only if Sharéa wants modules released on a schedule; otherwise leave all-access.

Lantern Notes (reflection stations)

Add one at the end of each Part (A, B, C, D). Full paste-ready copy is in the master doc (GlowStrm_Accessibility_Course_MASTER_forEboni.docx). Each station has three pieces:

  1. Shared lantern → build as a Discussion lesson. Learners post their note and read the trail others left. Completion: mark complete on post.
  2. Reflection → build as an Assignment / text-response lesson (completion: mark complete on submit). These are visible to Sharéa as the course guide — that's intended, for support and accountability.
  3. Say so, plainly. Each station includes a short privacy note telling learners the guide can see their reflection, that it's only to support them and keep them to their word (if they want that), and that no other learners see it. Paste that note in — don't skip it.
  4. Encourage a personal log — the copy invites learners to keep their own private notebook for anything more intimate they'd rather not share.

Style & formatting reference

Every lesson should feel like GlowStrm. Match these colors, fonts, and patterns. When Ruzuku's editor can't do something exactly, get as close as its options allow — consistency matters more than perfection.

Brand colors

Charcoal#271F41
Signal Gold#E6B65C
Deep Plum#783E8D
Rose#BB4072
Coral#FB896D
Plum Violet#774ECE
Cream#F8F4EE
Body text#1A1528

Hard rule

Flat colors only — no gradients, ever. Use gold for accent rules and highlights, plum for labels, rose for emphasis. Don't introduce colors outside this palette.

Typography

HeadingsThe SeasonUse Cormorant Garamond if The Season isn't available in Ruzuku. Left-align always.
Body textSource Sans 3All paragraphs, labels, and lists.
TaglineWhat grows, glows.Exactly this — lowercase, italic, gold. Never retype it differently.

Lesson layout pattern

  • Open each lesson with a short plum kicker label (the module/topic), then a serif heading.
  • Keep paragraphs to 2–4 sentences. Break dense blocks up — the original course reviews flagged "dense text" as the #1 issue.
  • Use a gold divider or spacing between sections rather than walls of text.
  • One idea per lesson; 5–15 minutes of content each. Split anything longer.
  • Close with the activity/prompt so the learner does something.

Do

  • Left-align all headings
  • Real heading styles (H2/H3), not bold-only text
  • Descriptive link text ("Ruzuku launch checklist"), never "click here"
  • Alt text on every image; captions on every video
  • Consistent spacing & heading sizes across all modules

Avoid

  • Gradients, drop shadows, off-brand colors
  • Pasting raw Word styling into the editor
  • Emoji inside the learner content
  • Huge single videos with no captions
  • Different layouts module to module

Accessibility = the brand here

This is an accessibility course, so formatting is the message: strong color contrast, real heading structure, alt text, captions, and descriptive links. If a lesson isn't accessible, it isn't on-brand.

Clarity checklist

Run this quick pass on each lesson after you paste it in — before you mark "Clarity-checked" in the tracker.

  • Reads cleanly out loud — no half-sentences, no leftover build-notes or answer-key text that belongs only in the source doc.
  • Placeholders filled — no stray brackets like [name] or [link] (Module 0's story is the known one to watch).
  • Links work — click every external link; confirm it resolves to the right page.
  • Headings make sense — a learner scanning just the headings can follow the flow.
  • Terms are consistent — e.g., "Trusted Tester," "WCAG," "Section 508" spelled and capitalized the same way throughout.
  • Facts match the corrected baseline — Trusted Tester training is ~85 hours (the ~20-hour figure refers only to the W3C foundation course).
  • The activity is clear — the learner knows exactly what to do at the end of the lesson.
  • Media loads — videos play and show captions; images show and have alt text.

Anything you're unsure about, don't guess — flag it for Sharéa in the module notes and keep moving. Better to leave one lesson unchecked than to ship a wrong fact.
